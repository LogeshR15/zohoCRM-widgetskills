# ZET Dev Workflow — Local Development to Deployment

> **⚠ Verification status: UNVERIFIED.** The ZET CLI command set, generated project layout, and
> `zet validate` limits below have not been checked against an authoritative Zoho source (unlike
> `references/sdk.md`). Confirm against `zet --help` and the current ZET release notes before
> relying on specifics.

## 1. Install ZET (one-time)

```bash
npm install -g zoho-extension-toolkit
zet --version   # should print 1.0.28 or later
```

## 2. Create a new widget project

CRM supports non-interactive init — always prefer this over interactive `zet init`:

```bash
# Creates ./MyWidget/ with the full project scaffold
zet init --zoho-service CRM --project-name MyWidget

cd MyWidget
```

Generated project structure:
```
MyWidget/
├── plugin-manifest.json   # Service metadata — edit this to add widget locations
├── package.json           # Express dev server dependencies
├── package-lock.json
├── app/
│   ├── widget.html        # Widget UI entry point
│   └── translations/
│       └── en.json        # i18n strings (empty by default)
├── server/
│   └── index.js           # HTTPS dev server on port 5000
├── node_modules/          # After npm install
├── cert.pem               # Self-signed cert — generated by zet run
├── key.pem                # Private key — generated by zet run
└── ZET-debug.log          # ZET activity log
```

**After init, immediately edit `plugin-manifest.json`** to add your widget location and URL:
```json
{
  "service": "CRM",
  "modules": {
    "widgets": [{ "location": "crm.record.detail", "url": "app/widget.html" }],
    "connectors": []
  },
  "config": []
}
```

## 3. Start local dev server

```bash
zet run
```

Output:
```
Zet running at https://127.0.0.1:5000
Note: Please enable the host (https://127.0.0.1:5000) in a new tab and
authorize the connection by clicking Advanced -> Proceed to 127.0.0.1 (unsafe).
```

**Required cert-trust step (one-time per browser):**
1. Open `https://127.0.0.1:5000` in your browser
2. Click **Advanced** → **Proceed to 127.0.0.1 (unsafe)**
3. You'll see the app directory listing — this means the server is trusted

The dev server:
- Serves `app/` as static files at `https://127.0.0.1:5000/app/`
- Serves `plugin-manifest.json` at `https://127.0.0.1:5000/plugin-manifest.json`
- CORS open (`*`) for all origins
- Port 5000 by default (widgettest uses 5001 to avoid conflicts)

## 4. Load widget in CRM

1. In your CRM account, go to **Setup → Marketplace → Extensions for CRM → Widgets**
2. Choose **Create Widget** → **ZET Widget** (or **Load from local server**)
3. Enter widget URL: `https://127.0.0.1:5000/app/widget.html`
4. Select the target module/location
5. Navigate to a record in CRM — the widget iframe will appear

> The widget runs inside CRM in a sandboxed iframe loaded from your localhost.
> `ZOHO.embeddedApp.init()` triggers the CRM host to inject PageLoad data.

## 5. Validate before packing

```bash
zet validate
```

Common errors and fixes:

| Error | Fix |
|-------|-----|
| `"modules" key missing` | Add `"modules": { "widgets": [...], "connectors": [] }` to manifest |
| `[WIDGETS] : location missing` | Each widget entry needs a non-empty `"location"` key |
| `[WIDGETS] : url missing` | Each widget entry needs a non-empty `"url"` key |
| `mandatory missing for config` | User-defined config must have `"mandatory": true/false` |
| `secure missing for config` | User-defined config must have `"secure": true/false` |
| File too large | Keep each file under 5 MB; total under 20 MB |
| Too many files | Max 250 files in the project |
| Invalid extension | Only `.html .js .css .json .txt .md .xml .jpg .png .gif .svg .mp3 .mp4 .woff .woff2 .ttf .eot` |

## 6. Pack for deployment

```bash
zet pack
```

Creates `dist/widget.zip` containing all files from `app/` and `plugin-manifest.json`.
The `server/`, `node_modules/`, `*.pem`, and `ZET-debug.log` are excluded automatically.

## 7. Deploy to Sigma / CRM Marketplace

### Option A — Manual upload via Sigma console

1. Go to [marketplace.zoho.com](https://marketplace.zoho.com) → Developer Portal → My Extensions
2. Create a new extension → Zoho CRM → Widget
3. Upload `dist/widget.zip`
4. Fill in name, description, icon, screenshots
5. Submit for review or install privately to your org

### Option B — Push via ZET CLI (requires Sigma login)

```bash
zet login                  # opens browser auth for Sigma account
zet whoami                 # verify login + workspace
zet list_workspace         # switch workspace if needed
zet push                   # push current build to Sigma
```

### Option C — Cloud run for staging

```bash
zet cloud_run              # deploy to Sigma cloud sandbox (no zip upload)
# ... test in CRM with the Sigma-hosted URL ...
zet cloud_stop             # stop the cloud run
```

### Option D — Pull an existing extension

```bash
zet pull                   # fetch extension source from Sigma to local
```

## 8. Multiple simultaneous widget projects

If you have multiple widget projects open at once, they'll conflict on port 5000.
Edit `server/index.js` in the second project to use a different port:

```javascript
var port = 5001;   // change from 5000
```

Then register the widget in CRM using `https://127.0.0.1:5001/app/widget.html`.

## 9. Adding translations (i18n)

`app/translations/en.json` maps keys to display strings:
```json
{
  "widget_title": "My CRM Widget",
  "loading": "Loading record…",
  "error": "Failed to load data"
}
```

Access in widget JS — the SDK has **no** translation helper (there is no `ZOHO.CRM.META.translate`),
so load and apply the strings yourself:

```javascript
fetch("/app/translations/en.json")
  .then(r => r.json())
  .then(t => { document.getElementById("title").textContent = t.widget_title; });
```

For locale detection see the i18n section of `references/troubleshooting.md` — it requires a hop
through `CONFIG.getCurrentUser()` then `API.getUser({ID})`, because `getCurrentUser` does not
include a `language` field.

## Debugging tips

- Check `ZET-debug.log` in the project root for CLI errors
- Open browser DevTools in the widget iframe (right-click → Inspect in Chrome)
- The widget iframe has its own console — all `console.log` output appears there
- If `ZOHO.embeddedApp` is undefined, the SDK script tag is missing or loading after widget JS
- If `PageLoad` never fires, ensure `ZOHO.embeddedApp.init()` is called at script load time (not inside an event handler)
- CORS errors on API calls usually mean the manifest `cspDomains.connect-src` is missing the target URL
